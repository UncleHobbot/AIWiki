## 🔥 Top News

**[Mythos: Anthropic's Frontier Cybersecurity Model](../wiki/agents/mythos-cybersecurity-agent.md)**
Claude Mythos Preview sits above Opus in Anthropic's model hierarchy. It became the first AI to autonomously complete AISI's "The Last Ones" — a 32-step simulated corporate network attack estimated to take human experts ~20 hours. Newer checkpoint: 6/10 completions. It also produced the first public macOS kernel memory corruption exploit on Apple M5 hardware and found a 27-year-old OpenBSD vulnerability. GPT-5.5 has since matched 2/10 completions. Cybersecurity researchers are treating Mythos as a capabilities threshold moment.

**[Figure AI 03: 30+ Hours Without a Battery](../wiki/news/figure-ai-03-robot-30-hours.md)**
Figure AI's humanoid robot ran a full warehouse shift for over 30 continuous hours powered by an external cable — effectively demonstrating unlimited uptime. The livestreamed event showed a coordinated team of robots working alongside human colleagues with minimal errors. Figure AI CEO Brett Adcock confirmed the robot also reached human walking speed during the stream.

**[GitHub Copilot Pricing Exodus](../wiki/news/github-copilot-pricing-exodus.md)**
GitHub moved Copilot from a flat-rate subscription to usage-based pricing. For heavy users (agent-heavy, large repos, Sonnet 4.5), April bills landed at 10–15× the previous monthly cost. Community response was sharp: a significant fraction of developers publicly migrated to Claude Pro ($20/month), Codex ($20/$100), or OpenCode Go. GitHub defended the change as reflecting real compute costs; critics argued it undermined Copilot's value as a predictable monthly tool.

**[OpenAI Launches $100/Month Max Tier](../wiki/news/openai-100-dollar-tier.md)**
OpenAI's new $100/month "Max" plan offers higher limits on GPT-5, o3, and o4-mini — plus early access to new models. Positioned to compete directly with Claude Pro at $20 and the emerging Codex $100 tier. Community reception was mixed: praised for removing hard rate limits but questioned for the price jump versus alternatives.

**[Roo Code Shuts Down, Pivots to Roomote](../wiki/news/roo-code-shutdown-roomote.md)**
Roo Code, a widely-used open-source Claude Code fork with extended MCP support and custom model routing, shut down its free tier and pivoted to Roomote — a remote agent platform. The Roo Code repository is archived. Most power users migrated to Claude Code (for hooks), OpenCode (for multi-provider routing), or Cline.

## 🛠️ New Tools & Releases

**[Poetiq: Recursive Self-Improvement Delivers New SOTA Coding](../wiki/tools/poetiq-recursive-self-improvement.md)**
Poetiq's self-optimizing harness — using Gemini 3 Flash as base model — surpassed Claude Opus 4.7 on multiple coding benchmarks. The key mechanism is recursive self-improvement: the harness generates its own evaluation criteria, runs itself against them, and refines its prompting strategy across iterations. Challenges the assumption that frontier model quality is the ceiling.

**[Orthrus-Qwen3: 7.8× Tokens/Forward with Frozen Backbone](../wiki/tools/orthrus-qwen3-acceleration.md)**
A hybrid diffusion+autoregressive architecture injected into Qwen3-8B achieves up to 7.8× throughput with provably identical output distribution. The backbone is frozen — no accuracy loss. Orthrus outperforms speculative decoding (EAGLE-3: 3.5× acceptance length vs Orthrus: 11.7×) and requires no external drafter model or separate KV cache. [Paper: arXiv 2605.12825](https://arxiv.org/abs/2605.12825)

**[Sparky: Fully Offline Suitcase AI Robot](../wiki/tools/sparky-offline-edge-ai-robot.md)**
An NVIDIA Jetson Orin NX Super (16GB unified memory) running Gemma 4 E4B via llama.cpp, packaged in a suitcase. Achieves ~200ms cached TTFT with 30+ sensors injecting live environmental context into every prompt. No cloud, no WiFi, no API keys. Covered by Tom's Hardware as a reference design for fully air-gapped embodied AI.

**[AgentMemory: Persistent Memory for AI Coding Agents](../wiki/tools/agentmemory.md)**
Open-source persistent memory layer for coding agents (Claude Code, Codex, Gemini CLI). Uses a 51-tool MCP server, semantic + episodic memory tiers, and achieves 95.2% recall at R@5. ~$10/year to run on cloud storage. Solves the "cold start" problem where agents re-derive context on every session.

**[Open Source Models vs Claude Opus: Real-World Benchmark](../wiki/models/open-source-models-vs-opus-copilot-benchmark.md)**
Burke Holland's GitHub Copilot benchmark: Qwen 3.6 27B (via API) wins on coding tasks at $4.90 vs Opus's $40 — an 8× cost advantage. GLM 5.1 is runner-up. MiniMax M2 scores well on long-context tasks. Key finding: for routine coding assistance, open-source models at instruction-following level are competitive with frontier models at a fraction of the cost.

**[Learn Harness Engineering (Walking Labs)](../wiki/concepts/learn-harness-engineering-course.md)**
A free 12-lecture online course on agent harness engineering. Key empirical claims: switching from a single CLAUDE.md to a modular instruction structure raised agent task success from 20% to ~100% in internal experiments. WIP=1 discipline (one active task per agent) improved 30-day completion rates from 37% to 86%. Session entropy analysis showed teams maintaining clean-state discipline had a 97% build pass rate vs 68% for those who didn't.

## 💡 Tips & Techniques

**[10 Ways to Stop Hitting Claude's Usage Limits](../wiki/tips/claude-usage-limits-token-management.md)**
From @0x_kaize: token costs compound quadratically with conversation history length. The top 10 fixes: (1) rewrite prompts rather than correcting previous ones, (2) start a new chat every 15–20 messages, (3) merge multiple prompts into one, (4) use Projects for shared doc caching across sessions, (5) disable User Memory for task-focused chats, (6) turn off Search and Connectors when not needed, (7) route routine tasks to smaller/cheaper models, (8) know the 5-hour rolling usage window, (9) avoid peak hours (10am–2pm EST), (10) skip Extended Thinking for non-reasoning tasks.

**[LLM Project Memory via Git: Plan-Execute-Distill Loop](../wiki/tips/llm-git-knowledge-accumulation.md)**
A version-controlled workflow for making LLM coding sessions compound: (1) write a short plan (max 3–4 sentences) in the repo; (2) execute with LLM assistance; (3) close out by documenting what happened vs. plan; (4) distill only reusable knowledge into playbooks and a DECISIONS.md; (5) commit everything. The distillation step is where most people quit — and it's the only step that accumulates value across sessions. "Prompting is praying. Verification is how you get real results."

**[Karpathy's 3-Strategy System: Wiki + Auto-Research + Context Engineering](../wiki/tips/karpathy-llm-knowledge-base-auto-research.md)**
Three complementary layers: (1) LLM Wiki — distilled, human-curated knowledge that survives context resets; (2) Auto-research loop — automated daily/weekly enrichment of wiki from monitored sources (RSS, subreddits, GitHub trending); (3) CLAUDE.md context engineering — structured project-level instructions that prime the agent with the right mental model before any task begins. Together they approach a "persistent senior engineer" who never forgets your codebase.

**[Agent Lifecycle Hooks in Copilot CLI and Claude Code](../wiki/tips/agent-lifecycle-hooks-copilot-vscode.md)**
Hooks fire at lifecycle events: PreToolUse (validate/gate before a tool runs), PostToolUse (log results, trigger downstream tools), SessionStart (inject context), SessionEnd (clean up state). Pattern: a PreToolUse hook running ESLint before any file write prevents the agent from creating code that immediately fails CI — catching issues before they enter the conversation context.

**[Claude Code Frameworks: Superpowers, Ouroboros, Han, Sandcastle](../wiki/tools/claude-code-frameworks.md)**
Community comparison of the four major Claude Code skill frameworks. When to adopt one: only when you're hitting the limits of raw Claude Code + CLAUDE.md, or repeating the same custom instructions in every session. Han (testdouble) is notable for: adversarial verification, YAGNI-encoded protocols, evidence requirements for all outputs, and agent swarms. Sandcastle is gaining traction as a lighter alternative. Start by writing 3-5 custom skills yourself first — then adopt a framework if you still need structure.

## 📚 Concepts Learned

**[Agent Harness Engineering](../wiki/concepts/agent-harness-engineering.md)**
The discipline of designing the scaffolding around an LLM: context assembly, tool exposure, agent loop, and evaluation. Core principle (Addy Osmani, O'Reilly 2026): *"Anytime you find an agent makes a mistake, you take the time to engineer a solution such that the agent never makes that mistake again."* A great harness with a decent model consistently beats a great model with a bad harness. The harness — not the model — maintains state and encodes institutional memory.

**[Memory and Skills Are the Same Harness](../wiki/concepts/memory-skills-unified-harness.md)**
@tricalt's architectural insight: memory persistence and skill invocation are not separate plugin layers — they're the same mechanism (markdown context files injected by the harness via the same path). Treating them as a "memory plugin" + "skills plugin" creates two integration surfaces where there should be one. The unified view: memory is context that persists across sessions; skills are context that activates for specific tasks — both are markdown files the harness decides to include.

**[Agent Operating System: 6-Component Kernel](../wiki/agents/agent-operating-system.md)**
IBM Technology's framework: an Agent OS manages AI agents the way an OS manages processes. The 6 components are: (1) Scheduler (which agents run when, with what priority), (2) Memory Manager (working/episodic/semantic tiers), (3) Tool Manager (capability registry and permission enforcement), (4) Identity Manager (role assignment, impersonation boundaries), (5) Observability (logs, traces, metrics), (6) Guardrails (safety constraints, compliance boundaries). Enables multi-agent coordination without coupling agents directly to each other.

**[Self-Guided Self-Play for LLMs (SGS)](../wiki/concepts/self-guided-self-play.md)**
LLM self-play plateaus because the Conjecturer (problem generator) learns to hack its reward by generating unsolvable noise. SGS adds a third Guide role that scores synthetic problems on relevance to real targets and naturalness — preventing collapse. Applied to Lean 4 theorem proving: a 7B model after 200 rounds of SGS solved more problems than a 671B model pass@4. [Paper: arXiv 2604.20209](https://arxiv.org/abs/2604.20209)

**[AI Agents: ARR Framework and OODA Loop](../wiki/concepts/ai-agents-arr-framework-ooda-loop.md)**
ARR = Atomic (one clear, bounded task), Reliable (deterministic given clear input), Reversible (no permanent side effects without checkpoint). Agents that violate any of these properties fail at scale. OODA loop mapping: agents Observe (tool calls + context), Orient (reasoning over observations), Decide (next action), Act (tool execution). The framework predicts where agents will fail: wide goal specifications lead to orientation failures; irreversible tools without guardrails lead to catastrophic Act failures.

**[Learn Harness Engineering: 5-Subsystem Model](../wiki/concepts/learn-harness-engineering-course.md)**
The Walking Labs course models a harness as 5 subsystems: Instructions (what the agent knows), Tools (what it can do), Environment (where it operates), State (what it remembers), Feedback (how it learns from outcomes). Each subsystem has a failure mode: underspecified Instructions cause goal drift; too many Tools cause decision paralysis; unmanaged State causes session entropy. The course provides cold-start tests for each: a passing cold-start test means the subsystem is self-contained enough to survive context resets.

## 💡 Советы и техники

**[10 способов перестать упираться в лимиты Claude](../wiki/tips/claude-usage-limits-token-management.md)**
Затраты на токены растут квадратично с длиной истории диалога. Топ-10 практик: перезаписывать промпты вместо исправлений, новый чат каждые 15–20 сообщений, объединять промпты, использовать Projects для кэширования документов, отключать Memory/Search/Connectors для рабочих чатов, маршрутизировать рутинные задачи на меньшие модели, знать 5-часовое скользящее окно, избегать пиковых часов, не использовать Extended Thinking для нерассуждательных задач.

**[Накопление знаний проекта через Git](../wiki/tips/llm-git-knowledge-accumulation.md)**
Версионированный рабочий процесс: план → выполнение → закрытие задачи → дистилляция → коммит. Шаг дистилляции — единственный, который даёт долгосрочную ценность. DECISIONS.md хранит «почему», а не «что». «Промптинг — это молитва. Верификация — вот что даёт реальные результаты.»

**[3-стратегическая система Karpathy](../wiki/tips/karpathy-llm-knowledge-base-auto-research.md)**
Три взаимодополняющих уровня: (1) LLM Wiki — дистиллированные знания, переживающие сброс контекста; (2) цикл автоматического исследования; (3) инжиниринг контекста через CLAUDE.md. В совокупности — «постоянный старший инженер», который никогда не забывает кодовую базу.

**[Хуки жизненного цикла агентов в Copilot CLI и Claude Code](../wiki/tips/agent-lifecycle-hooks-copilot-vscode.md)**
PreToolUse/PostToolUse/SessionStart/SessionEnd. Паттерн: хук PreToolUse запускает ESLint перед любой записью файла — агент не создаёт код, который немедленно ломает CI.

**[Фреймворки Claude Code: Superpowers, Ouroboros, Han, Sandcastle](../wiki/tools/claude-code-frameworks.md)**
Сравнение четырёх основных skill-фреймворков. Совет сообщества: сначала напишите 3–5 своих навыков — потом принимайте фреймворк, если всё равно нужна структура. Han выделяется: антагонистическая верификация, YAGNI, требование доказательств для всех выходных данных.

## 📚 Изученные концепции

**[Инженерия агентных жгутов](../wiki/concepts/agent-harness-engineering.md)**
Дисциплина проектирования обёртки вокруг LLM: сборка контекста, экспозиция инструментов, агентный цикл, оценка. Принцип Addy Osmani: «Каждый раз, когда агент делает ошибку, инженерно решите это так, чтобы он никогда не повторил её». Хороший harness с посредственной моделью превосходит хорошую модель с плохим harness.

**[Память и навыки — это один и тот же harness](../wiki/concepts/memory-skills-unified-harness.md)**
Архитектурный инсайт @tricalt: память и навыки — не отдельные слои плагинов, а один механизм (markdown-файлы, внедрённые harness). Единый взгляд: память — контекст, живущий между сессиями; навыки — контекст, активирующийся для конкретных задач.

**[Операционная система агентов: ядро из 6 компонентов](../wiki/agents/agent-operating-system.md)**
Фреймворк IBM Technology: планировщик, менеджер памяти, менеджер инструментов, менеджер идентичности, наблюдаемость, ограждения (guardrails). Позволяет координировать мультиагентные системы без прямой связи между агентами.

**[Самонаправленная самоигра для LLM (SGS)](../wiki/concepts/self-guided-self-play.md)**
Добавление роли Guide, оценивающей качество синтетических задач, предотвращает коллапс Conjecturer. 7B-модель после 200 раундов SGS решает больше задач доказательства теорем в Lean 4, чем 671B-модель pass@4. [arXiv 2604.20209](https://arxiv.org/abs/2604.20209)

**[AI-агенты: фреймворк ARR и цикл OODA](../wiki/concepts/ai-agents-arr-framework-ooda-loop.md)**
ARR = Atomic (одна чёткая задача), Reliable (детерминированный при чётком вводе), Reversible (нет необратимых побочных эффектов). OODA: агенты Наблюдают → Ориентируются → Решают → Действуют. Широкие цели вызывают сбои ориентации; необратимые инструменты без guardrails — катастрофические сбои действия.

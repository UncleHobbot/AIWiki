Что такое RAG?

Retrieval-Augmented Generation

Введён Lewis et al. (Facebook AI Research, 2020). Техника, которая заземляет ответы LLM в конкретном корпусе документов — без дообучения модели на этом корпусе.

  • Документы разбиваются на фрагменты (chunks) → каждый превращается в числовой эмбеддинг → хранится в векторной базе данных
  • При запросе: вопрос пользователя тоже преобразуется в эмбеддинг, находятся наиболее похожие фрагменты, они вставляются в промпт LLM как контекст
  • LLM отвечает, опираясь на найденные фрагменты — не на знания из обучения
  • Работает для любой предметной области без переобучения — просто меняйте корпус
Главное обещание: LLM остаётся точным и актуальным, потому что находит доказательства в момент запроса, а не хранит доменные знания в весах модели. — Lewis et al., «RAG for Knowledge-Intensive NLP Tasks», NeurIPS 2020

LLM + Ответ

RAG силён, когда: корпус огромен (миллионы документов), часто меняется или нужны точные ссылки на исходные фрагменты.

Слепое пятно RAG: при каждом запросе понимание выводится заново — синтез из нескольких источников, долгосрочные рассуждения и накопленные инсайты между вызовами не сохраняются.

Проблема

Знания, которые исчезают

  • Каждая сессия LLM начинается с нуля — без памяти о предыдущих рассуждениях
  • RAG повторно выводит выводы из сырого текста при каждом запросе
  • Люди создают вики, а потом бросают их — затраты на поддержку растут
  • Перекрёстные ссылки устаревают; противоречия накапливаются незаметно
«Ни один из существующих AI-инструментов не сохраняет знания между запусками — каждый раз они начинают с нуля.» — Авторы PARNESS, arXiv:2605.05258

Узкое место RAG

  • Поиск возвращает фрагменты, а не синтезированное понимание
  • 85% усилий агента тратится впустую на поиск (Pinecone, 2026)
  • 50–60% успешного выполнения задач с агентным RAG
  • Векторные индексы требуют специализированной инфраструктуры
  • Синтез из нескольких источников пересчитывается заново при каждом вызове

Основная идея

Аналогия с компиляцией

Вы не запускаете исходный код при каждом вызове — вы компилируете его один раз в бинарник и запускаете его.

// Разработка ПО compile(source_code) → binary run(binary) // быстро, многоразово // LLM Wiki ingest(raw_docs) → wiki_pages query(wiki) // без повторного вывода

GitHub Gist под названием llm-wiki.md — «файл-идея», предназначенный для вставки в любой LLM-агент, который затем адаптирует паттерн под конкретный домен.

Трёхуровневая архитектура

1
Сырые источники → inbox/ + sources/
Неизменяемая база истины. Веб-клипы, PDF, транскрипты, твиты. Никогда не редактируется — только пополняется. «Исходный код».
▼
2
Вики → wiki/
Markdown-файлы, управляемые LLM. Перекрёстные ссылки, двуязычность, синтез. «Скомпилированный бинарник». Знания накапливаются — не пересчитываются заново.
▼
3
Файл схемы → CLAUDE.md / AGENTS.md
Управляет инъекцией контекста. Сообщает агенту: как структурировать страницы, как связывать концепции, что делать с каждым типом источника. Ключевое нововведение — одна строка на домен.

Навигационные файлы: index.md — каталог всех страниц  ·  log.md — хронологическая история. Вместе позволяют LLM ориентироваться в ~100–500 источниках без инфраструктуры эмбеддингов.

Три операции

INGEST
Новый источник → LLM читает → создаёт или обновляет 10–15 страниц вики.

Перекрёстные ссылки строятся заранее. Противоречия помечаются сразу. Каждый ingest обогащает систему.
→
QUERY
LLM читает скомпилированную вики, синтезирует ответ.

Хорошие ответы сохраняются как новые страницы — система документирует собственные рассуждения.
→
LINT
Периодический аудит: поиск противоречий, страниц-сирот, устаревших утверждений, сломанных ссылок.

Обязателен. Без Lint галлюцинации закрепляются навсегда.

Ключевой риск: В чистом RAG галлюцинация влияет на один ответ. В LLM Wiki неверно понятый источник может быть записан как «факт» и распространиться через перекрёстные ссылки на 15 страниц до того, как кто-то заметит. Lint — ваша страховочная сеть.

Настройка за 5 шагов

1
Установите Obsidian (бесплатно) — создайте новое хранилище. Создайте три папки: raw/, wiki/, templates/.
2
Вставьте гист Карпатого в Claude Code. Попросите создать claude.md под ваш домен — ответьте на уточняющие вопросы.
3
Положите первый источник в raw/ — markdown-клип, PDF или текст. Запустите: "Я добавил новый источник. Обновите вики, пожалуйста."
4
Claude напишет 5–15 страниц вики, обновит index.md, запишет лог. Откройте граф Obsidian — увидите формирующуюся структуру знаний.
5
Повторяйте: добавляйте источники, периодически запускайте "Пожалуйста, сделайте lint вики." и задавайте синтезирующие вопросы. Вики накапливается.

Инструменты

Просмотрщик: Obsidian — граф, обратные ссылки, поиск. Не AI-инструмент — просто читалка markdown.

Агент: Claude Code, Codex или Cursor. Любой, кто читает и пишет файлы на вашей машине.

Предел масштаба: ~100–200 источников без инфраструктуры эмбеддингов. Дальше: qmd для гибридного поиска BM25/vector.

«Скучная часть ведения базы знаний — не чтение и не мышление, а рутина. Люди бросают вики, потому что бремя обслуживания растёт быстрее ценности. LLM не скучают.» — Андрей Карпаты

Петля саморазвития

Усвоение полезных навыков

Вики наблюдает, какие объяснения резонируют — часто запрашиваемые страницы получают более богатые перекрёстные ссылки. Агент развивает доменную интуицию из паттернов истории запросов. Пробелы в знаниях выявляются как отсутствующие страницы при аудите сломанных ссылок.

«Кража» идей у похожих проектов

PARNESS ввёл память с индексацией по противоречиям между сессиями. SurveyGen-I ввёл память терминов «не объяснять повторно». LightRAG ввёл двухуровневые графы сущностей/концепций. Каждый — импортируемый паттерн, без векторной БД.

Обучение на истории сессий

log.md — полный журнал аудита. Соотношение созданных и обновлённых записей показывает, растёт ли вики здоровым образом. Счётчик сирот отслеживает качество интеграции. Сломанные ссылки — накопленный технический долг.

Корректировка поведения по ошибкам

Галлюцинации, выжившие в страницах вики, становятся обучающими примерами для промпта Lint. Схема CLAUDE.md эволюционирует на основе наблюдаемых режимов отказа — ужесточение правил уровней источников, добавление деревьев категоризации, уточнение двуязычного шаблона.

Эффект накопления: Каждый новый источник обогащает вики. Каждый запрос, превращённый в страницу, добавляет перекрёстные ссылки. Каждый проход lint убирает шум. Система становится лучше как вики со временем — не просто больше.

Открытые проблемы

Обнаружение противоречий

Сейчас: замечается вручную при Lint. Академическое решение: консенсус 9 агентов KARMA — извлечь ключевые утверждения из каждой новой записи, сравнить с записями той же категории.

scripts/check_conflicts.py → auto-populate ## Debate в обеих записях

Реляционный поиск

Текущий поиск: полнотекстовый ripgrep. Пропускает: «какие инструменты используют RAG?» Подход LightRAG: после каждой записи — вызов Claude для извлечения отношений → запись в .state/relations/slug.json.

Без векторной или граф-БД.

Согласованность дайджестов

Проблема: еженедельный дайджест заново объясняет понятия прошлой недели. Исправление SurveyGen-I: после каждого дайджеста записывать digests/memory.json → вводить как ограничение «не объяснять повторно».
